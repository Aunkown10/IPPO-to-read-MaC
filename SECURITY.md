# Security notes for Ippo to Read v0.1

## Scope

The intended protection is confidentiality and integrity of the app-managed
private library **at rest**, under a strong passphrase, while its key is not
available to an attacker. This is an unaudited implementation and requires
native build/runtime testing and independent review before serious use.

The private library is not an undetectable folder and not a secure operating
system. Normal-library data is not encrypted.

## Storage and authentication

- Vault format: version 1, Argon2id v0x13 with 64 MiB, 3 passes, 1 lane and a
  random 16-byte salt, deriving a 32-byte key. Parameters are fixed for this
  format; upgrades need an explicit migration.
- Encryption: AES-256-GCM, fresh 12-byte random nonce per encryption, 16-byte
  authentication tag. Blob envelope is `IPPO1 || nonce || ciphertext || tag`.
- Associated data: `ippo/v1/<book-id>/<resource-name>`. Private record metadata
  uses resource name `metadata`. A separate authenticated verifier validates
  a supplied password without storing it.
- The SQLite database exposes UUIDs, privacy flags, ciphertext lengths and
  the vault salt/verifier. Private titles, ordering metadata, thumbnails and
  bookmarks are inside authenticated encrypted payloads.
- The native session key uses `Zeroizing<[u8; 32]>`. Password input is not logged
  or persisted by this code. JavaScript strings, decoded documents, image
  surfaces, library metadata clones and IPC buffers are not guaranteed to be
  wiped from physical memory. A `zeroize` wrapper is not whole-process erasure.
- A small in-process retry delay follows incorrect passwords. It is not a
  substitute for a strong passphrase and does not stop offline guessing.

## Access checks and application boundaries

Every private list/read/write/delete/transfer goes through native session
checks. Public APIs select public records explicitly. Content-read commands
accept a validated book ID and index, not an arbitrary filesystem path.
Native file selection authorizes imports. Imported originals are never deleted.

Only the bundled main webview receives capabilities. No shell, generic
filesystem, arbitrary SQL, remote domain or webview-creation permissions are
granted to JavaScript. Custom Rust commands are local application commands.
The production CSP does not allow remote scripts or general outbound requests.
PDFs render to canvases; DOCX is parsed for raster image references, not HTML
or executable document content. Normal builds bundle their PDF.js worker,
CMaps, fonts and WASM locally after npm dependency installation.

## Import handling

Archive filenames are never used as extraction destinations. Managed resource
names and storage directories are generated by the app. Unsafe ZIP paths,
symlinks, duplicate entry names and suspicious expansion ratios are rejected.
Resource sizes and pixel counts are limited. Private imports and privacy
transfers write encrypted bytes directly into staging directories.

The importer is not a sandboxed process. Bugs in image, archive, XML or PDF
parsers may still cause resource exhaustion or other vulnerabilities. Keep
dependencies patched; treat hostile or very unusual files as untrusted.

## Lifecycle and limitations

The primary session key is dropped on manual lock, native idle timeout,
application focus loss (except native selection dialogs), or process exit.
The app suppresses private UI on blur and destroys its private reader surfaces
on lock. Pending native operations share a mutex; a lock can wait for an
already-running operation. Frontend concealment is independent of that wait.

An app cannot provide reliable secrecy against malware running as the same
user, an administrator, a debugger, screenshots, memory inspection, an unlocked
session or a compromised dependency. The OS/browser can page or cache memory.
No screenshot prevention, memory locking, backup exclusion, biometric unlock,
keychain wrapping or trusted execution environment is implemented.

Original filenames, file-picker history, OS indexes, old public copies, deleted
blocks, filesystem journals, existing backups and storage counts/sizes remain
outside this protection. SQLite `secure_delete` and removing an old managed
copy do not guarantee forensic erasure, especially on SSDs and copy-on-write
filesystems. Import private material directly into the vault when possible.

## Recovery and release gates

There is no password reset, password-change UI or recovery key. Back up the
whole closed app-data directory and keep the passphrase separately. Do not
remove originals before verifying imports and restoration from a backup.

Before distributing a release: resolve and commit dependency lockfiles; run
all tests on supported operating systems; audit npm/Cargo dependencies; review
CSP/capabilities; exercise interrupted imports and disk-full handling; obtain
independent security review; and configure signed/notarized installers and
an update strategy. These steps have not been claimed as completed here.

## v0.3 online metadata privacy

Online series information is optional and applies only to the normal library.
When enabled and a normal comic shelf is opened, Ippo may send the shelf/series
title (not the comic file, pages, bookmarks, or private-library contents) to
read-only public metadata providers such as Jikan/MyAnimeList and ComicK.
Successful results are cached locally. Private shelves never trigger these
lookups. Disable **Online series info** in Settings for a fully offline library
experience.

Reading-time totals are stored inside each managed book record. Private-book
reading time therefore remains inside the encrypted private metadata payload.


## 0.3.2 classification boundaries

- Online classification validates a real stored book ID and rejects private books before network requests. Private classification reports are encrypted inside book metadata.
- Only fixed Jikan, MangaDex and AniList hosts are queried by the classifier. Publisher/download links are never fetched as arbitrary URLs. Redirects are disabled and each JSON response is capped at 2 MiB.
- Catalogs are fallible. Ambiguous matches need confirmation; visual layout does not establish origin. User-pinned types are not overwritten by automatic checks.
- The optional original CBZ/ZIP metadata re-read uses the existing bounded, traversal/symlink-safe archive reader and creates no extra chapter. It cannot recreate metadata discarded by previous releases if the original no longer exists.
- A version-5 library should not be opened with an older binary. Rollback requires the corresponding app-data backup, not just an old project folder.
